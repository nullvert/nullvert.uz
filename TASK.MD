Ты опытный frontend и DevOps-инженер. Твоя задача — развернуть и настроить статический блог на базе темы Shirone в текущей открытой папке `blog` с использованием официального npm-пакета `shirones`.

### Первоисточники и документация
Перед выполнением задачи ориентируйся на официальные материалы темы:
- Документация Shirone: https://docs.shirone.mysqil.com/
- Wiki пакета shirones: https://github.com/yCENzh/shirones/wiki
- Референсный репозиторий темы: https://github.com/LyraVoid/Shirone

### КРИТИЧЕСКИЕ ПРАВИЛА И ОГРАНИЧЕНИЯ:
1. НЕ выполняй Git-команды (`git init`, `git add`, `git commit`, `git push`, переключение веток). Пользователь будет версионировать проект и делать коммиты вручную.
2. Не навязывай устаревшие фиксированные версии пакетов и утилит. Проверь текущее системное окружение пользователя (`node -v`, `pnpm -v`) и используй актуальные версии инструментов, совместимые с ядром Shirone и Astro.
3. Блог настраивается под кастомный домен (CNAME) на GitHub Pages.
4. Соблюдай принцип «Zero-burden» темы: не подключай и отключи в конфигурации неиспользуемые внешние сервисы, CDN и аналитику, чтобы сборка была полностью автономной.

### План выполнения задачи

#### 1. Инициализация через пакетный режим
- Проверь доступность менеджера пакетов pnpm в системе.
- Инициализируй проект официальной командой:
  `npx shirones init` (или `pnpm dlx shirones init`)
- Убедись, что созданы базовые файлы и структура:
  - `package.json` с подключенным пакетом `shirones`
  - `astro.config.mjs`
  - Каталог конфигурации (модули `siteConfig.ts`, `navBarConfig.ts`, `profileConfig.ts` и т.д.)
  - Каталог контента `src/content/posts/`
  - Каталог статики `public/`
- Установи зависимости в соответствии с `package.json`.

#### 2. Конфигурация кастомного домена (CNAME)
- В каталог `public/` добавь файл `CNAME` с плейсхолдером (например, `blog.yourdomain.com`).
- В файле конфигурации сайта (`siteConfig.ts`):
  - Установи канонический URL: `site: "https://blog.yourdomain.com"`
  - Для кастомного домена укажи корень: `base: "/"`
  - Установи системный язык интерфейса: `lang: "ru"` (или другой предпочтительный язык).

#### 3. Настройка навигации и профиля
- В `profileConfig.ts` настрой карточку автора (имя, краткое описание, ссылки на профили GitHub, Telegram, Email, RSS). Убери ссылки на специфичные неиспользуемые платформы (Bilibili, Gitee).
- В `navBarConfig.ts` оставь основные навигационные разделы (Главная, Архив, Категории, Теги, Обо мне), скрыв разделы, контент для которых пока не заполнен (Moments, Anime, Devices и т.д.).
- Проверь `commentConfig.ts` и `musicConfig.ts`: если сервисы комментирования или внешние плейлисты не используются, убедись, что они отключены (`enable: false`).

#### 4. Инициализация контента
- Удали примеры демонстрационных постов, созданные инициализатором.
- Создай один аккуратный валидный пост `src/content/posts/hello-world.md`:
  ```markdown
  ---
  title: Привет, мир!
  published: 2026-09-30
  description: Первый пост в обновленном блоге на Shirone.
  tags: [Блог, Astro]
  category: Разное
  draft: false
  ---

  Тестовая публикация для проверки сборки и компонентов темы.


  5. Пайплайн GitHub Actions (.github/workflows/deploy.yml)
Создай workflow деплоя на GitHub Pages. Сделай его гибким к версиям окружения:

Используй actions/checkout@v4.

Для настройки pnpm используй pnpm/action-setup с автоматическим определением версии (или чтением поля packageManager из package.json).

Для Node.js используй текущую стабильную ветку через actions/setup-node@v4 с кешированием pnpm.

Шаги сборки: установка зависимостей -> диагностика (pnpm check, pnpm type-check) -> билд (pnpm build).

Деплой артефакта папки ./dist через официальные экшены actions/upload-pages-artifact и actions/deploy-pages.

6. Локальная проверка
Запусти локальную сборку (pnpm build) и убедись, что:

Код завершения равен 0;

Директория dist/ успешно сгенерирована;

Поисковый индекс Pagefind создан;

Файл CNAME корректно скопирован в dist/CNAME.

Выведи отчет о созданных файлах и точные места в конфиге, где пользователю нужно указать свой домен.
